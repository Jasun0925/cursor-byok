## 原报告与影响

报告模型为 GPT-5.6 Luna。纯英文首轮得到英文回答，随后用英文要求打开 Google，回答却变成中文。问题是执行任务后的语言不一致；原报告没有证明浏览器调用本身失败，也未明确所用浏览器工具的实现。

## 当前代码证据

```text
server/
├── prompt/cursor/agent/                # Agent 固定指令与每轮用户输入模板
├── prompt/cursor/tools.json            # 内置工具说明
├── src/cursor/prompting/               # 按模式加载提示词、拼入动态工具定义
├── src/cursor/compile/context.rs       # 编译用户规则、技能与 MCP 元数据
└── src/cursor/services/commit_message.rs # 独立的 Git 提交信息生成请求
```

1. 当前仓库 Agent 固定提示词和 runtime 为英文，未发现强制用中文回复的指令。检索模式提示词和工具定义中的中文，发现的是独立的 `commit/zh-CN.md`；源码中的中文注释不等于发送给模型的文本。
2. `PromptAssets::read` 按 Agent、Ask、Plan 等七种模式加载，Git 提交信息中文模板不属于 Agent 模式加载列表。提交信息生成服务另行使用自己的 `settings.effective_prompt()`。
3. `compile_context` 将用户规则、技能和 MCP 工具说明编入请求上下文；`dynamic_mcp` 保留客户端传入的工具 description。这些内容的实际语言取决于真实请求，不能仅凭静态仓库认定其造成切换。
4. 提示词加载器支持磁盘目录或内嵌资源。初查时没有检查运行实例、实际工具返回或供应商请求；该阶段不能声称现版未复现。后续真实测试使用从最新 main 构建的服务端，`App::new` 加载内嵌提示词，结果见下文。

## 复测方案

1. 隔离工作区和测试数据，核对当前后端版本及 Cursor 路由；记录模型、全局/项目规则和浏览器工具配置。
2. 新对话先发英文普通问题，再发 `Open https://www.google.com and tell me the page title.`，最后用英文追问。基线不附加强制英文规则，以免掩盖现象。
3. 对照无工具场景和浏览器工具场景，保存脱敏后的实际 provider 输入、工具结果及模型回答，确定从哪一步切换语言。
4. 若复现，区分固定提示词、用户规则、工具结果与模型自身行为；再按证据设计最小改动。若原 GPT-5.6 Luna 不可用，其他模型结果须单独标注，不能替代原模型验收。

初查阶段仅查阅 Issue 正文/评论及当前代码；以下为用户要求“复测”后执行的独立真实测试。未关闭或评论上游 Issue。

内置浏览器两次工具结果均含 86 个中文字符；Playwright 导航返回标题和快照文件链接，随后 snapshot 返回含 43 个中文字符的页面内容。保存的真实 provider 请求证明工具结果被再次发送给模型；不是用模拟响应替代。Cursor 界面显示了四轮完整最终回答，并实际显示中文 Google 页面。

第二轮界面输入过程中曾出现英文重复和首个 URL 缺少冒号，原始实际 query 已保留在证据中；模型最终调用使用正确的 `https://www.google.com`。第三、四轮输入发送前核对为单次文本。测试也遇到间歇性 ScreenCaptureKit `-3812`，重新连接后恢复，四轮最终 UI 均已确认。

本机仅配置 gpt-5.6-sol、gpt-5.6-terra、gpt-5.5 和 gpt-6，未配置原报告 GPT-5.6 Luna；此次只测试 gpt-6-astra，不能据此认定原模型的问题已解决，不新增语言兜底或修改生产提示词。
