# Issue #449：动态子代理模型名称与本次指定优先

原报告：[leookun/cursor-byok#449](https://github.com/leookun/cursor-byok/issues/449)。本次用户明确授权：本次在对话中指定的模型优先于 Cursor 子代理设置，修改后发布。

## 最终行为

新建子代理时：**显式 Task.model → Cursor 子代理设置 → 父模型**。工具说明要求仅在用户明确指定另一模型时填写显式 ID，其余使用 `inherit`。省略 model 或使用 inherit 时采用 Cursor 设置；显式继承设置则采用父模型。禁用子代理仍然优先阻止调用，不能通过显式模型绕过。恢复既有子代理的行为未改变，不要求重选模型。

例如 Cursor 设置为 gpt-5.6-sol，用户要求用 gpt-5.5：主模型从最新上下文找到 gpt-5.5 对应 ID，Task 将该 ID 传给 Cursor，而不是替换成 gpt-5.6-sol。未知的显式 ID 不会自动替换为默认模型；交由现有执行路径报告错误。

客户端的动态名单与详情继续进入 `<subagent_models>` 上下文；客户端只传本地哈希时，从 BYOK 配置补齐显示名称。只补充本次已列出的 ID 与当前默认设置的名称，不扩充客户端名单，不投影凭据、端点或其他私有配置。同名模型保留不同 ID，不合并。

```text
server/
├── prompt/cursor/tools.json             # 稳定工具说明：显式指定优先，默认使用 inherit
├── src/cursor/compile/
│   ├── run.rs                          # 从本地配置提取 ID → 显示名称
│   ├── model.rs                        # 编译动态名单、名称及默认设置
│   ├── break_messages.rs               # 追加请求上下文，不改写历史前缀
│   └── subagent_models_tests.rs         # 名称变化、重放、转义与选择规则回归
├── src/cursor/tools/runtime.rs          # 决定本次 Task 的实际模型 ID
└── tests/
    ├── subagent_model_context.rs        # transport → provider 的哈希名称回归
    ├── tool_round.rs                   # 实际发给 Cursor 的模型 ID 与禁用限制
    └── prefix_stability.rs             # 稳定工具定义及历史前缀验证
```

请求 → 编译动态模型上下文 → 追加 canonical 历史并持久化/checkpoint → provider 读取名称及 ID → Task 指定模型 → runtime 应用优先级 → Cursor 收到 SubagentArgs.model_id → 子代理执行及结果返回。

没有移动或删除模块，也没有数据库迁移。名单或名称改变时追加新消息；相同内容不重复追加；A→B→A、重试、checkpoint 恢复不改写旧消息。工具定义不会随每轮名单变化。

## 验证与真实测试范围

- 第一版删除固定名单后，用户真实 Cursor 测试的已配置模型子代理完成，父代理正常接回结果；5 次请求 HTTP 200。见 [第一轮证据](2026-10-08-issue449-ui-evidence.json)。
- 后续按名称指定 gpt-5.5 暴露空名称缺口。哈希名称 transport 回归修复前失败、修复后通过，包含不泄露凭据/无关配置的断言。
- 名称补修的真实会话确认 gpt-5.5 存在，并按当时旧规则准确解释设置冲突，工具调用数为 0。见 [名称补修证据](2026-10-08-issue449-name-fix-evidence.json)。这是历史验证，不是新优先级的真实执行证据。
- 优先级回归修复前失败：显式 requested-hash 发到 Cursor 后变成 configured-hash。修复后检查显式指定、Cursor 默认、省略/inherit、父模型以及不静默替换未知 ID 的实际 SubagentArgs。
- 禁用子代理的两条路径均测试显式模型无法绕过；没有发送 ExecServerMessage，工具结果为错误。
- 工具说明变更仅更新 Agent/Ask/Plan/Debug/Multitask 的固定 schema 摘要。

最终验证结果及 v1.0.12 发布操作见 [发布记录](2026-10-08-v1.0.12-release.md)。新优先级尚未经过用户真实 Cursor 点击复测；不能将之前旧规则的冲突截图算作其成功证据。未更改子代理按类型分别选取 override、Fast 或 thinking effort 的行为。
