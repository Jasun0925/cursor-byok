## 修改后的结构

```text
server/src/cursor/compile/
├── context.rs            # 收集规则，普通规则和手动选择规则共用编译逻辑
├── rules.rs              # 输出正文、来源、类型及适用条件，并说明目录范围
├── break_messages.rs     # 比较最新请求上下文，仅在内容变化时追加消息（既有逻辑）
├── run.rs                # 组织本轮上下文、用户消息和执行输入（既有逻辑）
└── rule_scope_tests.rs   # 元数据、范围变化、去重和检查点回归
server/tests/
└── rule_scope.rs         # 经实际 Transport/Run/SQLite 路径捕获 FakeProvider 请求
```

规则序列化从 `context.rs` 提取到 `rules.rs`；普通规则与手动选择规则的两套正文输出由同一个实现替代。未改供应商适配层、系统提示、协议定义或数据库结构，也没有新增依赖。

```text
Cursor AgentRunRequest / 规则 Blob
    → hydrate：读取完整 CursorRule
    → context.rs：收集 rules、non_file_rules、cloud_rule
    → rules.rs：保留 full_path、type、globs、scoped_to、description、frontmatter
    → compile_request_context：与最近一份上下文按内容比较
        相同 → 不重复追加
        改变 → 新 request-context:<event> → 本轮 runtime 消息
    → SQLite / checkpoint：保存并恢复消息身份和内容
    → ModelRequest.history → 各供应商序列化 → 模型

手动附加规则 → selected_context → 同一个 rules.rs → 本轮用户上下文
```

- AGENTS.md 的指令适用于所在目录和后代目录；更深层的 AGENTS.md 在其子树内优先。
- file_globbed 规则保留每条匹配表达式；agent_fetched 规则保留描述；Global、FileGlobbed、AgentFetched、ManuallyAttached 保持可区分。
- 保留 Cursor 给出的 `scoped_to` 和 frontmatter，不猜测其值、不按本机文件系统解析客户端路径；元数据中的 XML 特殊字符转义，规则正文保持原样。
- 普通无元数据规则、本地规则和云端正文继续传递；原有空正文/技能过滤保留。
- 不根据当前提示删掉其他目录规则。同一对话 `前端范围 A → 后端范围 B → 前端范围 A` 追加三份独立上下文，旧消息保持不变；同内容的新轮次、重试及检查点恢复不重复追加。
