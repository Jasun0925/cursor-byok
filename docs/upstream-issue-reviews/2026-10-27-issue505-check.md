# Issue #505：多个思考签名的恢复失败

结论：**当前源码可复现 checkpoint 拒绝第二个签名；尚未修复，也未复现原作者网关的完整生成路径。** 原生 Anthropic 多个签名块能够经过 checkpoint 并进入下一次 HTTP 请求；OpenAI Chat 的多次 `reasoning_content` delta 也只生成一个完整 replay state。不能把两者等同于多次 `ProviderReplayState` 事件。

- 本地基线：`facafefbe69d6e1980f47ada3ee8bc7718b82182`。本次只增加/加强测试与记录，没有改变生产协议或历史存储。

## 已验证路径

```text
server/
├── src/provider/anthropic.rs                # 聚合一轮的签名块为一个 replay state
├── src/provider/openai_chat.rs              # 聚合 reasoning_content 为一个 replay state
├── src/run/model_cycle.rs                   # 接收一轮唯一的完整 replay state
├── src/cursor/checkpoint/messages/
│   ├── encode.rs                           # 将完整 replay state 编码到一个 reasoning signature
│   └── decode.rs                           # 从 Cursor 历史恢复；第二个 signature 会报错
└── tests/
    ├── anthropic_signature.rs              # HTTP/SSE → checkpoint → 下一次 HTTP 请求
    └── chat_think_tags.rs                   # 多段 reasoning delta → 单个 checkpoint 状态
```

| 输入与检查 | 结果 | 能证明的边界 |
| --- | --- | --- |
| 手工构造两个不透明 Cursor signature，再调用真实 `decode` | 失败：`Cursor assistant has multiple reasoning signatures` | 解码缺口确实存在；不证明原网关产生该结构 |
| 手工构造两个 BYOK Anthropic replay envelope，再调用真实 `decode` | 同样失败 | 即使每个 envelope 本身有效，当前仍拒绝第二个 |
| 原生 Anthropic 两个 signed thinking + redacted thinking，checkpoint 往返后发送下一次 HTTP 请求 | 通过，块与签名顺序一致 | 本地可控 HTTP/SSE，非真实供应商 |
| 两个 signed thinking，恢复工具消息及结果，再追加下一轮 | 通过，第一条助手请求内容保持一致 | 工具调用/结果由测试构造，未运行真实 Cursor 工具 |
| OpenAI Chat 两段 `reasoning_content`，中间插入正文 | 通过，聚合为 `firstsecond`，checkpoint 只有一个 signature，往返内容相等 | 当前支持的字符串 delta 格式；不代表未知网关的签名扩展 |

当前 OpenAI Chat 适配器读取 `reasoning_content` / `reasoning` 字符串，没有把任意网关签名解释为 Anthropic 的逻辑。已有外来 provider state 隔离测试也通过。直接把不透明 Cursor signature 当成 Anthropic signature，或删除第二次状态检查并覆盖前一个，都不能满足“原样按顺序回放”。

[保存的测试源码](reproductions/issue505_checkpoint.rs) 包含两个“应该成功恢复”的断言，在上述基线上均失败，Cargo 退出码 101。它保留在证据目录，不加入常规 CI，也没有把错误行为写成必须维持的通过断言。要复现，在仓库根目录执行以下 Python；它只临时创建独立测试目标，结束时移除，不覆盖同名已有文件：

from pathlib import Path
import subprocess

source = Path("docs/upstream-issue-reviews/reproductions/issue505_checkpoint.rs")

finally:
    target.unlink()
