之前的真实 Cursor 验证证实过文字补全、迟到事件防重复、真实模型追问及 Shell 结果回传；后续又验证过 Skipped→Ran 的工具状态修复。这些证据没有明确验证“点击展开工具详情”，因此工具详情问题不能据此关闭。

## 本次测试

先执行已有测试：

```text
cargo test -p cursor-server --test responses_text --test tool_presentation
Responses 文本测试：9 / 9 通过
工具展示/事件顺序测试：8 / 8 通过
```

随后添加临时诊断测试，通过 HTTP SSE 输入以下三类事件：

| 场景 | 预期文本 | 实际文本 | 结果 |
| --- | --- | --- | --- |
| 仅 response.completed.output 携带完整文字 | `Review complete.` | 空字符串 | 失败 |
| delta 只给前缀，完整文字仅在 response.completed.output 中 | `Review complete.` | `Review ` | 失败 |
| delta + output_text.done + output_item.done + 完整快照 | `Review complete.`，只出现一次 | 与预期一致 | 通过 |

失败用例是模拟中转省略逐项结束事件的边界输入；不是声称标准流一定会省略这些事件。现有实现已容忍部分非完整事件序列，本次明确测出该最终快照路径不在已修复范围内。

最小失败输入：

```json
{
  "type": "response.completed",
  "response": {
    "status": "completed",
    "output": [{
      "type": "message",
      "id": "msg_review",
      "role": "assistant",
      "status": "completed",
      "content": [{"type": "output_text", "text": "Review complete.", "annotations": []}]
    }],
    "usage": {"input_tokens": 3, "output_tokens": 2}
  }
}
```

## 代码定位

```text
server/
├── src/provider/openai_responses.rs  # 解析 Responses 事件，将文本及结束状态送入运行层
├── src/run/model_cycle.rs           # 累计模型文本、工具调用和用量，返回本轮结果
└── tests/
    ├── responses_text.rs            # HTTP/SSE 文本补全与防重复回归
    └── tool_presentation.rs         # Cursor 协议事件顺序与 checkpoint 重放回归
```

```text
模拟中转 HTTP/SSE
  → OpenAiResponsesProvider
      output_text.done / output_item.done → 补全文字
      response.completed → 读取 usage、结束工具/文本流、输出 Done
                           未读取 response.output 中的文字
  → consume_model_cycle
  → 返回 Stop + 空文本，或 Stop + 未补全的前缀
```

已有 #501 修复的是每个 output item 的累计文本基线；这次缺口是最终 response 快照未进入该补全路径。它不推翻已有 9 项测试的结论，但说明不能由此推出“所有空白输出都已修复”。
