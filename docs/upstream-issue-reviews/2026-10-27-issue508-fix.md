## 断点与修复

锁定依赖为 reqwest 0.12.28 / hyper-util 0.1.20。后者 `client/proxy/matcher.rs` 的 `Builder::from_system` 在创建 matcher 时读取环境变量及系统设置。现有 `NetworkClients` 会长期保存三种客户端；原设置 API 只在用户保存 BYOK 自定义代理时调用 `invalidate`，系统设置变化不会经过该 API。

```text
server/
├── src/network.rs                       # 三种客户端缓存、定时检查及统一失效
├── src/network/proxy_fingerprint.rs     # 读取与 reqwest 路由有关的配置输入（新增）
├── src/provider/router.rs               # 每次内置模型请求取 provider 客户端（未改）
├── src/api/cursor/proxy.rs               # Cursor 转发取 cursor 客户端（未改）
├── src/control/service.rs               # 管理请求取 default 客户端；保存设置立即失效（未改）
└── tests/network_proxy_refresh.rs       # 独立子进程中的真实 HTTP 路由与流式响应测试
```

```text
请求取用客户端
  → 缓存的上次检查是否已过 2 秒
  → 读取持久化设置 + 有关环境变量/系统配置
  → 指纹相同：复用连接池
  → 指纹变化：清空 default / cursor / provider 三个缓存槽
  → 按当前配置创建客户端 → 发出请求

切换前：已发出的请求/响应流持有旧客户端
切换时：统一缓存失效，不取消旧请求
切换后：新取用的客户端使用新配置，旧响应流可正常结束
```

检查与缓存变更使用同一写锁，锁内再次检查时间，避免并发检查覆盖较新的结果。读取失败保留现有缓存，并仍按检查间隔限频。日志只记录变化或读取失败，不输出代理地址、认证内容或指纹值。

配置输入：

| 模式/平台 | 检测内容 |
| --- | --- |
| BYOK 自定义代理 | 地址、认证开关；开启认证时包括用户名及密码。忽略无关系统代理/环境变化 |
| 系统模式，所有平台 | HTTP/HTTPS/ALL/NO_PROXY 的大小写变量及影响 CGI 代理行为的 REQUEST_METHOD |
| macOS | SCDynamicStore 的 HTTP/HTTPS Enable、Proxy、Port，与锁定 hyper-util 所读取的六个键一致 |
| Windows | 当前用户 Internet Settings 的 ProxyEnable、ProxyServer、ProxyOverride，与锁定 hyper-util 相同 |

`system-configuration 0.7` 和 `windows-registry 0.6` 原本已在锁文件依赖图中，本次列为 server 对应平台的直接依赖；没有升级依赖版本。只检测 reqwest 当前支持的设置，不扩展 PAC 等协议能力。

## 复现与验证

测试通过独立子进程改变该进程的环境变量，使用当前线程 runtime、本地 HTTP 端点、临时数据库；既不修改 macOS/Windows 系统代理，也不连接真实供应商。

1. 修复前，两项路由测试均失败：系统模式切到 B 后仍收到 A；直接更新持久化认证后仍发送旧认证。
2. 修复后，两项测试全部通过，各自包含多步断言：
   - 三种缓存客户端均切换 A→B→NO_PROXY 直连→A。
   - 配置不变时跨检查周期继续复用原 TCP 连接。
   - 清空缓存期间已开始的响应流仍收到尾块并正常结束。
   - 配置仍要求走已停止代理时请求失败，不偷偷直连目标。
   - cursor 的禁止重定向、default 的默认重定向、provider 的超时均保留。
   - 自定义代理模式下系统环境变化不重建连接；密码及地址变化被采用。
   - 显式 `invalidate` 立即生效；真实关闭 Store 连接池后，配置读取失败仍保留已建立的客户端。
3. macOS 的合成 CFDictionary 验证开关、主机、端口、HTTPS 设置变化及禁用代理时无关字段不影响指纹；另一次只读调用确认本机系统配置可读取。
4. 全工作区 **451 项通过，0 失败、0 忽略**；全工作区所有目标 Clippy、格式与 diff 检查通过。详细结果见[结构化证据](2026-10-27-issue508-evidence.json)。
5. 已推送的 `e0fc76e` 对应 [CI #40400813950](https://github.com/haohaomin/cursor-byok/actions/runs/40400813950) 完成成功：Linux、Windows、macOS 和 Frontend 四项均通过。CI 不替代上述系统设置 UI 的未完成验收。

## 可用性与限制

检查在获取客户端时触发，间隔 2 秒；已经拿到旧客户端的调用不会自动重新发出。并非所有网络故障都属于代理缓存问题；代理仍启用但服务已停止时，保持失败是正确行为。

本次证明真实 reqwest 缓存和重建后的 HTTP 路由，未冒充用户在 Clash UI 切换的实测，也未验证 Windows 桌面设置切换或 HTTPS CONNECT。当前安装包 v1.0.17 不包含此修复。上游归档只读，修复说明只能保留在本 fork，没有成功评论。
