# #155：忽略纯进度通知，保留完成通知恢复

> 2026-10-18 复核更正：本轮确实消除了 invalid_argument，但成功空流缺少 Cursor 要求的 TurnEnded，会被判为可重试连接中断。因此“已验证”仅限原错误不再返回，不能代表客户端完整接收。已补修，见 [流结束修复](2026-10-18-issue155-stream-end-fix.md)。

## 结果

修复了 Cursor 后台 Shell 输出通知触发 `Error resuming chat` 的问题。Cursor 在输出匹配时可能先发送只有 `TaskProgress` 的通知；BYOK 之前过滤掉该条目后把空集合报成协议错误。现在纯进度通知直接以成功结束，不启动模型 Run；收到 `TaskFinished` 时仍按原逻辑生成一次恢复轮次。

## 改动

```text
server/src/cursor/compile/insert_messages.rs
  project(...) -> Result<Option<Projection>>
  无 TaskFinished → Ok(None)

server/src/cursor/compile/run.rs
  背景完成事件没有投影时不生成 event_id
  继续支持混合通知：跳过 TaskProgress，只投影 TaskFinished

server/src/cursor/conversation/background.rs
  识别纯进度背景通知为 Ignored

server/src/cursor/conversation/runtime.rs
  Ignored 直接发送成功结束帧
  兼容已有 continuation 路径的空背景投影

server/tests/conversation_delivery.rs
  增加纯进度通知回归：无错误、无模型调用、无运行记录
```

没有放宽 `TaskFinished` 的字段校验，也没有把进度通知伪装成完成通知。重复的完成通知仍通过已有事件 ID 去重。
