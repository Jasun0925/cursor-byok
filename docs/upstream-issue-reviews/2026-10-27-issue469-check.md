## WebFetch：单独失败，不能算完整远程支持

同一 SSH 窗口访问公开 `https://example.com`。模型获得本机 `http://127.0.0.1:49588/web-cache/<uuid>.txt` 引用，随后把 URL 当作 Read 路径，报 `file not found`，最终回复 `WEBFETCH_REMOTE_FAILED`。

这里的 Read 用法本身不正确，因此另做主机归属检查：同一缓存 URL 在本机返回 HTTP 200、176 bytes、包含 Example Domain；远端绕过环境代理直接请求同一 loopback URL，得到 `[Errno 111] Connection refused`。这证明即使按当前工具提示用 Shell 下载，该引用在远端也不可达；不表示短网页内联内容完全不可用，也没有测试长网页截断。

当前源码链路：

```text
server/src/search/cache.rs                         # 本机磁盘缓存及 loopback HTTP 地址
    ↓
server/src/cursor/tools/tool_call_result/interaction.rs # 模型收到缓存 URL，UI 收到本机 file_path
    ↓
Cursor 远程工具                                    # 在另一主机读取/下载，loopback 指向远端自己
```

PR 中的会话私有内容分页旨在消除这个主机边界问题，尚需独立实现/审查和真实长内容验收。Semble 绝对路径目前也在 BYOK 主机访问；原 PR 的远程快照方案尚未采用或实测。本轮不将任一项写成已修复。
