# #155 追加检测的两项修复

已修复迟到完成通知撤销压缩、完成通知跨批次重复唤醒两项服务端问题。先将 [检测探针](2026-10-18-issue155-audit.md) 纳入正式回归，分别观察到摘要计数 1→0、模型调用次数 1→2，再修改生产代码。修复后，两项原始失败及扩展回归通过。

## 行为与边界

| 场景 | 修复后的结果 |
| --- | --- |
| `/summarize` 后收到携带旧状态的 TaskFinished | 模型保留最新摘要，旧的等待回复不再回来；摘要计数、归档、根消息与 UI 轮次前缀保留 |
| 关闭连接池、重新打开数据库并重建服务后收到旧通知 | 同样保留摘要，证明恢复不依赖内存缓存 |
| `[A,B]` 成功后单独重发 `[A]` | 模型调用总数保持 1 |
| `[A,B]` 后收到 `[B,C]`，或 `[A]` 后收到 `[A,B]` | 只追加新任务；历史中每个任务恰好出现一次，旧历史保持结构前缀 |
| 上述批次全部倒序重发 | 只确认通知，不再调用模型 |
| `[A,B]` 正在执行时收到 `[B,C]` | C 加入同一个运行；B 不重复；总共一个 Run、两次模型调用 |
| 首次由官方链路转入 BYOK，或输入历史比本地新 | 保留输入中的新历史，原有回归继续通过 |

通知确认继续使用 `TurnEnded → Connect EOF`。取消后自动重发、TaskProgress 不启动模型、同一子代理不同任务身份等原有行为保持通过。

## 当前实现

```text
server/
├── src/cursor/compile/insert_messages.rs # 将每个完成任务编译成独立、确定身份的事件
├── src/cursor/compile/run.rs             # 按任务生成持久消息，合并本轮 UI 展示文本
├── src/cursor/conversation/background.rs # 逐事件准入；判断旧历史是否已被压缩归档
├── src/cursor/conversation/runtime.rs    # 投递到活动运行，或从选定状态创建新运行
├── src/cursor/checkpoint/worker.rs       # 发布前保存已完成检查点的 Cursor 状态
├── src/store/cursor_checkpoints.rs       # 按检查点及祖先读取持久化状态
├── migrations/0011_add_cursor_checkpoints.sql # 新增状态表及检查点外键
└── tests/conversation_delivery.rs        # 通知、去重、重启与压缩的协议回归
```

```text
完成通知 → 校验每个任务身份 → 内存占用 + 持久消息去重
  ├─ 全部重复 / 只有进度 → TurnEnded → EOF，不调用模型
  └─ 有新任务 → 编译新事件 → 投递
       ├─ 父 Run 活动中 → 原生命周期追加 → 下一次模型调用
       └─ 父 Run 已结束 → 检查输入历史
            ├─ 本地历史包含它，或压缩归档证明它已被替代
            │    → 本地当前规范历史 + 对应 Cursor 状态
            └─ 输入含有本地尚未见过的新历史 → 保留输入历史
          → 新 Run → 模型回复 → 保存检查点状态 → 发布 checkpoint
```

原有“整批身份作为持久事件”的路径已替换为逐任务身份；没有扫描或解析旧批次消息来添加兼容路径。旧的历史前缀判断继续用于正常追加；显式压缩通过已有归档中的根消息来识别，不能仅凭摘要计数或本地状态存在就覆盖较新的输入。

新增表仅保存检查点对应的 protobuf 状态，根消息、轮次和摘要继续引用现有 Blob。历史 SQL 迁移未改写。升级测试从版本 10 建库并保留会话消息，验证版本 11 升级、状态写入和更新、祖先读取、会话隔离、外键约束及关闭后重开。
