**检出两个尚未修复的服务端边界问题：迟到通知会撤销已完成的上下文压缩；完成通知改变批次后会重复唤醒模型。** 两个场景分别单独运行和组合复跑，均稳定失败。本轮只做检测，没有修改生产源码。

## 1. 迟到的完成通知会撤销压缩（P1）

```text
父对话回复“等待后台任务” → 保存此时的旧 checkpoint
  → /summarize 成功，当前历史替换成摘要，self_summary_count=1
  → TaskFinished 携带旧 checkpoint 到达
  → pending_base_checkpoint 发现新摘要不是旧历史的扩展
  → 选择旧 checkpoint
  → 模型重新收到压缩前历史，摘要消失，self_summary_count=0
```

实际输出：`summary_retained=false summary_count=0 old_waiting_retained=true`。模型确实继续了，但使用的是旧历史；这会抵消上下文压缩，重新带回本应移出的内容，可能再次触及上下文长度限制。

位置：[background.rs](../../server/src/cursor/conversation/background.rs)，`pending_base_checkpoint` 中仅以消息前缀是否匹配选择历史，未区分“初次接管的新历史”和“已被显式压缩替代的旧历史”。修复时需要保留压缩边界，同时保留上轮修好的首次接管场景；不能恢复成无条件选择本地 current。

## 2. 同一个完成事件改变批次后会再次调用模型（P2）

```text
收到 [任务 A 完成, 任务 B 完成] → 调用模型一次，处理成功
  → 随后只重发 [任务 A 完成]
  → 批次事件 ID 从 A:B 变成 A，现有去重查不到
  → 再次调用模型
```

预期模型调用次数为 1，实际为 2。当前去重针对整批事件身份，无法识别已经在别的批次消费过的任务。会导致重复回复或重复处理后续工作；本探针只生成文本，没有观察到 Shell 重跑，不能把“重复模型调用”写成“命令已重复执行”。

位置：[insert_messages.rs](../../server/src/cursor/compile/insert_messages.rs) 的批次 `message_id` 与 [background.rs](../../server/src/cursor/conversation/background.rs) 的 admission 查询。需要按单个完成事件保证幂等，再处理一批事件；同时保持不同任务、同一子代理的不同时次及重启后的身份边界。
