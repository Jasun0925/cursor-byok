## 实现路径

```text
server/
├── src/api/cursor/handlers.rs          分别读取两个可选父任务请求头
├── src/cursor/transport/handle.rs      原子补齐关联字段，拒绝空值或冲突值
├── src/cursor/compile/run.rs           用输入检查点位置标识缺省 ID 的子代理输入
├── src/cursor/conversation/runtime.rs  将已有父工具调用 ID 交给检查点构建器
└── tests/subagent_admission.rs         HTTP → 运行 → 持久化 → 检查点恢复回归
```

执行路径：Cursor BidiAppend → 本地路由 → 父元数据准入 → AgentRunRequest 编译 → 输入锚点与事件去重 → 供应商 → KV 确认 → 检查点与成功终止帧。

- 父请求 ID 和工具调用 ID 独立可选；缺省不清除已知值。后续追加可以补全缺失字段，但已知值不可改写。一次冲突更新不会部分修改元数据。
- 工具调用 ID 在运行准备时可用则继续用于父任务进度关联；本次不新增“运行已开始后重绑定父任务”行为。
- 仅对子代理的缺省消息 ID 作正规化，普通主对话缺少 ID 仍报错；客户端已有 ID 保持原语义。
- 缺省输入 ID 取传入检查点的根消息引用、轮次引用和摘要引用摘要值。事件内容仍走现有 user_event_id 计算；重试相同输入位置保持稳定，下一轮检查点变化则区分新输入。
- 不按纯文本相等合并轮次，不使用随机数或临时传输 request_id 代替消息身份；不修改数据库结构、供应商序列化或旧历史。
- 若客户端既不发消息 ID，也不发更新后的检查点，无法仅凭相同文本判断它是重试还是新轮次；本次不猜测该未提供区分信息的场景。
