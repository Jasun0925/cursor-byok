## 当前代码与结论

当前 OpenAI Chat 路径只按 `reasoning_content` / `reasoning` 字段识别思考，`content` 直接成为正文事件，不解析 `<think>`。本次六项回归在未修改生产代码的情况下全部通过，不能将原帖描述的异常状态归因于当前标签解析。

```text
server/
├── src/provider/openai_chat.rs # 读取实际 SSE，分离协议 reasoning 字段和正文 content
├── src/run/model_cycle.rs     # 聚合正文/思考并发送面向客户端的 RunEvent
└── tests/chat_think_tags.rs   # 本机 HTTP/SSE + RunEvent 回归，保留标签与后续文本
```

Antigravity 插件有专用标签清理逻辑，本次官方 API/OpenAI Chat 路径测试不覆盖该插件。

## 六项新增回归

| 场景 | 断言 |
| --- | --- |
| 完整 `<think>reasoning</think>` 后接正文 | 所有内容仍为正文，未转为思考 |
| 标签拆成多个 SSE delta | 每个片段和后续中文正文完整传递 |
| 未闭合 `<think>`，随后单引号和正文 | 单引号不触发终止；后续正文到达 |
| 只返回 `<think>`，供应商明确 stop | 原样保留标签，正常结束；没有虚构缺失内容 |
| `reasoning_content` 后接正文中的标签 | 结构化思考独立传递并记录回放状态，文本标签仍为正文 |
| `<think>` 与单引号后断流，无 finish_reason / DONE | 明确报告缺少终止标记的错误，并保留已收到的部分正文 |

测试经本机模拟 HTTP 服务、真实 OpenAI Chat SSE 适配器和模型执行周期，检查聚合结果及面向客户端的 RunEvent 顺序；不等同于 Cursor 界面端到端测试。
