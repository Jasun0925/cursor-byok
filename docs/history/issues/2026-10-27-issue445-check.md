### 不透明 token 的手动刷新

在 `38db686` 上新增三个宿主测试，Deno 进程加载实际 `grok-auth/resources.ts`，只替换网络响应。**三项全部失败**：没有有效期的 access token 被准备阶段跳过，额度查询 401 随即标记 invalid；刷新接口错误地返回成功，八路并发也没有发出任何 token grant。该失败来自公开的 `refresh_resource` 入口，不是另写一个续期算法模拟成功。

修复后的执行路径为：

```text
账号刷新 → 按需准备凭据 → 查询额度
                              │ 401：auth-error
                              ↓
                    释放额度查询占用的账号锁
                              ↓
                    宿主串行准备并保存轮换凭据
                              ↓
                    重新读取已保存凭据 → 只重试一次额度查询
                              ↓
                    保存额度补丁，或报告查询失败
```

准备与刷新共用账号锁；并发失败携带旧快照，已经轮换的 token 不会再被同一个旧 401 重复刷新。凭据先保存，后续额度接口再次返回 401 或 503 时也不会丢失新 refresh token。三项测试修复后全部通过，一次手动刷新得到新凭据及 75% 剩余额度，八路并发只交换一次令牌；第二次认证失败或额度暂时故障均停止并返回错误。

`resource.refresh` 现在明确返回 `completed { patch }` 或 `auth-error { message }`，宿主不再把认证失败当作账号状态补丁成功处理。此为插件协议变化：API 升到 **2**，三个内置插件一起适配并提高各自缓存版本，保证已安装代码会更新。旧 API 插件在 manifest 校验时拒绝，没有保留旧返回格式解析；外部插件需适配新协议后才能加载。此改动没有更新当前正式安装。
