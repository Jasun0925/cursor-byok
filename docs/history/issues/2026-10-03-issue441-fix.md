# Issue #441：Kimi K3 预设与 Moonshot 公共 API 分离

> 历史记录：状态、版本、路径及测试数仅对应记录日期；当前交付状态见 [工作状态](../../work-status.md)。复现脚本按文中基线使用，不作为当前生产操作步骤。

## 结论

上游 [#441](https://github.com/leookun/cursor-byok/issues/441) 的配置是 `https://api.moonshot.cn/v1` 加模型 `k3`，错误提示为 `this model is not available`。当前桌面预设原本把 Kimi Code 和 Moonshot 公共 API 混在一个 `Kimi (Moonshot)` 项目中：它填入 `https://api.kimi.com/coding` 和 `k3`，其中 `k3` 只适用于 Kimi Code 入口。

官方 Kimi K3 公共 API 文档要求：

```text
服务器： https://api.moonshot.cn/v1
模型：   kimi-k3
接口：   https://api.moonshot.cn/v1/chat/completions
```

因此最可能的原因是服务入口与模型标识混用。服务端会原样发送模型标识，不会把 `k3` 自动改写成 `kimi-k3`。

本次修复新增独立的 `Moonshot Kimi API` 预设，保留原有 `Kimi (Moonshot)` 作为 Kimi Code 预设：

```text
Kimi Code
  https://api.kimi.com/coding
  k3 / kimi-for-coding

Moonshot 公共 API
  https://api.moonshot.cn
  /v1/chat/completions
  kimi-k3
```

Moonshot 预设只提供 OpenAI 协议；Anthropic 协议下不会显示该 chip，也不会产生空 endpoint 配置。
