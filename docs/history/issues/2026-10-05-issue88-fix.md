# Issue #88：连通性测试缺少非空系统指令

> 历史记录：状态、版本、路径及测试数仅对应记录日期；当前交付状态见 [工作状态](../../work-status.md)。复现脚本按文中基线使用，不作为当前生产操作步骤。

原报告：[leookun/cursor-byok#88](https://github.com/leookun/cursor-byok/issues/88)。原帖错误为 `openai responses benchmark status=400`，正文为 `{"detail":"Instructions are required"}`。评论怀疑中转站透传配置，但没有提供可确定根因的完整请求。

## 当前缺口与修复

连通性测试原先构造 `instructions: ""`，Responses provider 将它原样写入 HTTP 请求。要求非空 instructions 的服务会拒绝该测试。

现在测试请求使用固定指令 `Follow the user's output format exactly.`，即“严格遵守用户要求的输出格式”。用户消息仍要求输出 1～120。

```text
server/
├── src/control/service.rs          # 构造独立的连通性测试请求；本次唯一生产代码改动
├── src/provider/router.rs         # 按模型配置选择供应商协议并记录调用
├── src/provider/openai_responses.rs # 序列化 instructions 并发送流式请求
└── tests/model_connectivity.rs     # 经真实路由和 HTTP/SSE 验证两类接口
```

测试没有加入工具、图片或既有对话。正常 Cursor 对话提示词、测试超时、成功判定、速度计算均保持原逻辑。没有在 provider 层给所有空指令自动填值。

## 验证

使用隔离 SQLite 配置和本机模拟 Responses 服务，调用真实 `ControlService::test_model` → `ProviderRouter` → HTTP/SSE 路径：

- 严格接口收到缺失、空白或空字符串的 instructions 时返回原报错 400。
- 宽松接口允许空指令和非空指令。
- 修复前：严格接口测试失败（同类 400），宽松接口通过。
- 修复后：两项均通过；断言输出正文、供应商 token 统计、首个有效响应时间、模型 ID、stream 开关、用户提示以及无工具请求。
- 服务端全量 326 项通过，Clippy（`-D warnings`）、格式与 diff 检查通过。全量验证结果见 [证据记录](2026-10-05-issue88-evidence.json)。
