# Issue #444：自动压缩不能静默丢弃早期任务

日期：2026-11-24。基线为 fork `be3fd7d`（PR #50 合并后），工作分支 `codex/issue444-compaction`。

## 结论与边界

原 [#444](https://github.com/leookun/cursor-byok/issues/444) 描述通过 grok2api 接入 Grok Free 后，压缩会遗忘旧任务并重复执行。原报告没有日志和摘要样本，不能认定下面的缺口就是原环境的唯一原因。

本轮已在当前生产路径独立复现两处自动压缩数据丢失：

1. 原 `trim_to_context` 在请求摘要模型之前删除最早的用户轮次。摘要模型根本看不到原目标和早期已完成事项。
2. 摘要出错、超时或被中断时，原兜底只保存序列化历史的最后 12,000 字符，并成功覆盖原检查点；可能既失去原任务，也从半截 JSON 开始。

候选改为按时间分批提供完整可见历史、将前一批摘要带入下一批，最后一次性提交。删除旧兜底路径；摘要失败或重建上下文仍不满足预算时，保留原历史并返回错误，不提交替代摘要。模型自身的摘要质量仍无法由确定性测试保证。

**范围：自动压缩。**手动 `/summarize` 仍使用现有完整历史请求及失败保留逻辑。没有 Grok 测试账号，没有运行真实 Grok/Cursor 验收，不标记原 Issue 彻底解决。

## 代码路径

```text
server/src/run/
├── compaction.rs          判断时机、预留上下文、校验结果
├── compaction/batches.rs  整理历史文本/图片/工具记录并按输入预算切片
├── engine.rs              Run 主循环，触发自动压缩并在完成后继续模型调用
└── engine/compaction.rs   有界摘要调用、消息中断、最终检查点提交

server/tests/
├── compaction/retention.rs  早期目标、分批传递、错误/截断/超时/取消保留
├── compaction/recovery.rs   摘要后失败与 SQLite/Cursor 检查点恢复
├── compaction.rs            自动/手动压缩、完整兜底、预算与用量
└── interrupt.rs             压缩中的新消息仍可继续同一 Run
```

原单次 `auto_compact` 从 `engine.rs` 移到 `engine/compaction.rs`；删除尾部裁剪路径及其“应丢弃 u1”的旧断言。普通非压缩 Run 的历史和 provider adapter 不变。

```text
已提交历史 + 当前请求
  → 分离当前请求、保留最新 request-context
  → 完整旧历史 → 投影/加载工具图片 → 有序片段
  → 摘要 1 → 摘要 1 + 片段 2 → … → 最终摘要
  → 验证重建预算
  → 一次 replace_checkpoint → 发布 Cursor 检查点并等待确认
  → 追加压缩中接收的新消息 → 同一 Run 继续
```

每批都为系统提示、前批摘要、操作说明和 4,096 输出 token 留出空间。未配置上下文窗口时从有限的 32,768 窗口估算开始，遇到供应商上下文拒绝则将批次窗口减半并重新分片，直到成功或已无法容纳；拒绝重试不会跳过源内容。超长文本在 UTF-8 边界切分，图片保留为图片；工具调用/结果作为带名称、ID 和结果状态的历史数据，避免跨批形成孤立的实时工具消息。非 ASCII 文本在原估算上增加 UTF-8 字节预留；这是保守估算，不宣称对所有供应商等同于精确 token 数。启用图像剥离时在分批前去掉图片，不加载工具图片 Blob。预算检查借用内容并累计成本，不重复复制图片字节。

助手私有 thinking 和供应商 replay 状态不进入摘要输入。工具结果带有不可信历史数据标注，系统指令要求只提取事实，不能把工具输出中的指令提升为用户目标；这不代表已证明所有模型都能抵御提示注入。

每次摘要调用仍有 30 秒上限。中途插入用户消息会取消当前调用，并重试相同片段；新消息在最终摘要后交付。显式取消终止当前 Run；任何未完成摘要均不写入检查点。无需开启新 Run 来完成正常的分批压缩。

## 复现与验证

先在旧实现添加行为测试，两项均失败：

- 早期任务回归：摘要请求中缺少 `ORIGINAL_GOAL`。
- 大历史摘要失败回归：原代码返回 `Success` 并用末尾片段替换历史，预期应失败并保留原数据。

修复后检查：

- 两轮累计超过预算时，早期目标、早期已完成任务和后期结果均进入摘要请求；第二批带上第一批摘要，继续调用带上最终摘要及当前待办。
- 中文、Emoji、换行密集文本的各批可按顺序完整拼回；图片与工具参数/结果保留，每批估算输入加输出预留均不超过预算。
- 过小窗口、过大的前批摘要无法容纳新片段时停止，不生成空摘要覆盖历史。
- 401、空摘要、输出上限截断、第二批失败、30 秒超时、第二批取消均保留原历史，不提交部分摘要。
- 小历史与大历史的摘要超时均返回失败并保留历史；摘要成功后再遇到模型错误，仍可从 SQLite/Cursor 检查点恢复。
- 压缩中插入用户消息会重试同一源片段，然后正常继续，协议回归通过。

首版全目标回归为 594 通过、0 失败、14 忽略；[PR #51](https://github.com/haohaomin/cursor-byok/pull/51) 审查后增加私有状态隔离、中文保守估算、有限默认窗口及拒绝重分片，并移除全部摘要兜底。新增中文约束在首版失败，修正后通过；最终本机回归共 **597 通过、0 失败、14 忽略**（38 组），包括 18 项 compaction 集成、23 项中断/队列回归；Clippy、格式与差异检查通过。新版跨平台 CI 待验，不能用首版 CI 代替。

本机验证使用现有命令级 macOS SDK/`ld64.lld` 参数，未改仓库构建配置。主要命令：

```bash

cargo test --locked -p cursor-server --test interrupt
cargo test --locked -p cursor-server -p semble-core --all-targets
```
