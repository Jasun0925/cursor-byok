## 修复后的行为

- Steer 保留原 Task 的执行，不把 exec 标记为 interrupted；普通 Read/Shell 等仍取消。
- 前台工具轮给保留的 Task 提交非错误的“仍在运行，稍后交付结果，请勿重启”返回值。
- Task 真正返回后，结果以新运行时消息追加到历史，原工具返回值保持不变；不会给同一工具调用补第二条 tool result。
- 结果按原 exec ID 路由，完成事件身份含原 run/round/call，避免下一轮复用 call ID 时串线。
- 父 Run 活跃时，通过现有 InsertMessages 在安全边界提交；正在结束／已结束时，由当前 transport 保留事件并启动父对话后续 Run，复用已编译的模型、提示词、工具与执行上下文。
- 有待交付 Task 时，不触发原来的 2 秒空闲关闭。显式 Cancel、同一 transport 中的 RunRequest 替换、失败及断连仍结束所有权，不因晚到结果恢复旧任务。

新增 `task.rs`。晚到 Task 的唯一接收权从前台 output 提升到 transport 所属的 Task 状态；保留已有 output 接收通道处理普通结果。没有移动或删除其他模块，没有新增数据库表、迁移或 provider 专属分支。

```text
原 Task / 原 exec
  → Steer：登记分离状态 → BreakMessages 结算前台等待 → 追加用户消息
  → 原 Task 返回
  → runtime 按 exec ID 找原始归属
  → 新 completion 运行时消息
      ├─ 父 Run 活跃 → InsertMessages → store 追加 → checkpoint → 下次模型请求
      └─ 父 Run 已结束 → 保留待交付事件 → 新父 Run → 同样的追加／发布路径

原 Task 的执行生命周期不变；只在需要消费晚到结果时创建新的父 Run。
```

结果解码与前台通道投递共用分离状态锁。Steer 登记分离后移交已入队结果，覆盖“结果已解码，但 output 尚未处理”的竞态。保留事件等待提交回执，避免把 `RunClosing`/`RunEnded` 当成成功送达。
