## 复现与修复

1. **上游协议协商失败。** 受控 TLS 服务同时支持 `h2` 和 `http/1.1`，生产 `client_builder` 与 `CursorProxy::forward` 发出的请求仍是 HTTP/1.1。基线 HTTP/2 断言失败，HTTP/1.1 对照通过。Cargo 对 reqwest 关闭默认 features 后，只启用了 `native-tls`，缺少 `http2` 和 `native-tls-alpn`。
2. **开启 HTTP/2 后取消不完整。** 先读到响应首块再丢弃响应，上传发送端在 5 秒内仍未收到 receiver 关闭信号。增加与响应生命周期绑定的 cancellation token：转发失败、请求 future 被丢弃、响应结束或被丢弃都会释放上传。

[reqwest 0.12.28 feature 定义](https://docs.rs/crate/reqwest/0.12.28/source/Cargo.toml.orig) 区分 HTTP/2 支持与 native TLS ALPN；[Connect 协议](https://connectrpc.com/docs/protocol/) 要求双向 RPC 使用 HTTP/2。本轮复现的是当前 BYOK 客户端的协商缺口，没有取得原作者的 Cursor 流量，因此不把它认定为原报告唯一根因。

## 结构与生命周期

```text
server/
├── Cargo.toml                         # 开启现有 reqwest 的 HTTP/2、ALPN；声明测试用 TLS/body 依赖
├── src/api/cursor/proxy.rs             # 转发请求/响应，响应生命周期控制上传取消
├── src/network.rs                     # 客户端缓存与代理设置；区分 Cursor 和普通客户端协议
├── src/network/streaming_tests.rs      # TLS 协商、交错上传/下载、已读与未读响应取消
├── src/local_app/proxy.rs              # 继续负责接管代理；仅注册新增测试模块
└── src/local_app/proxy_stream_tests.rs  # 真实 CONNECT、TLS/H2 到本地后端的双向数据对照
```

```text
Cursor → CONNECT/TLS/H2 → hudsucker → 本地 HTTP 后端
  → CursorProxy → NetworkClients（读取持久化代理设置）
  → reqwest TLS/ALPN → Cursor 上游

请求开始：上传流和响应共用一个取消信号
响应进行中：接收首块后仍可继续上传第二块
响应结束/丢弃，或转发失败：释放 guard → 取消上传 → 释放请求体
```

普通 provider、直接搜索、Semble 资源下载与开发前端代理的构建入口也显式使用 HTTP/1.1，避免 Cargo feature 合并扩大本次协议切换范围。未新增监听器或修改服务端路由。现有本地 HTTP 跳转在测试中能交错传输两块数据，未复现正文声称的“任何 HTTP/1.1 跳转必然死锁”。协议降级仍不能满足要求 HTTP/2 的上游服务，因此修复实际出站协商缺口。
