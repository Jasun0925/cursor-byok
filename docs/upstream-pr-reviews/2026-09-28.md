## 需要特别注意的证据

### #474：CI 通过，但实际不只是网络修复

[规则入口](https://github.com/leookun/cursor-byok/blob/24316e9642a8e6c3e048bb70a255c8200fe4f130/server/src/cursor/services/knowledge/mod.rs#L135) 在普通 add/update 路径以 info 级别记录完整规则正文；命中 `.blocklist` 时，add 返回成功和 `id="blocked"`，update 删除旧规则且忽略删除结果。[规则存储](https://github.com/leookun/cursor-byok/blob/24316e9642a8e6c3e048bb70a255c8200fe4f130/server/src/cursor/services/knowledge/store.rs#L145) 也会清理已落盘内容。这会造成规则内容进入日志，以及用户看到成功但数据未保存/被删除。**不建议整项合并。2026-10-27 已独立实现代理缓存修复并补齐隔离 HTTP 验证；源码未发布，系统 UI 切换待验，见[处理记录](../upstream-issue-reviews/2026-10-27-issue508-fix.md)。** 没有 `.blocklist` 时不触发黑名单删除，但正文日志仍存在。

### #433：硬编码拒绝请求早于正常分流

[本地代理](https://github.com/leookun/cursor-byok/blob/a5b1ce085d6a48e9fa83866f49dbb198ae753c70/server/src/local_app/proxy.rs#L134) 在检查 Cursor host、TAB Direct 分流之前匹配 `local_stub_status`，对 FileSync、BackgroundComposer 等接口直接返回 400/404；未检查账号是否真的没有这些功能。对依赖这些接口的用户会改变行为，不能视为纯粹的出站代理修复。Cargo 同时强制开启 `custom-protocol`，需要独立验证开发运行模式。

### #458：小 diff 也有安装行为变化

[证书安装](https://github.com/leookun/cursor-byok/blob/5b63b8586a22975114e955933022b1f3c64a9de4/server/src/local_app/ca/mod.rs#L91) 与 Windows 检测一起转到 CurrentUser，而既有 LocalMachine 证书不再被这段检测识别。应拆开终端参数修复和证书范围调整。上游行内 review 也指出此问题；本次未做 Windows 实机测试。

### #437 / #483：插件标题下还有共享基础设施改动

#437 新增 `0010_add_model_enabled.sql`，当前已有 0001–0009；新增迁移本身并非已证实缺陷，但不能省略旧库升级验证。其 [release workflow](https://github.com/leookun/cursor-byok/blob/c5d5de08ff922977ecf023d81ee3534d1454157b/.github/workflows/release.yml#L20) 加入贡献者仓库/分支发布逻辑，以及 Actions 版本、构建和更新包生成方式变化，不能直接套用到个人 fork。
