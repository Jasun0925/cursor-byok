## 行为与执行路径

```text
Cursor BidiAppend
  → handlers.rs：独立接收两个可选父任务头
  → transport/handle.rs：保留关联，拒绝空值与冲突
  → compile/run.rs：缺省子代理 ID 取检查点位置
  → 输入锚点和事件去重 → 模型 → 检查点与父任务进度
```

| 行为 | 当前 fork | 候选关键语义 |
| --- | --- | --- |
| 子代理缺省 message_id | 能启动、完成并保存 ID | 能启动，但内容相同就重用 ID |
| 同一输入的重试 | 不重复追加 | 同样不重复追加 |
| 下一轮重复同一句话 | 新检查点位置对应新的输入 | 重用旧身份，恢复到旧锚点，历史前缀检查失败 |
| 只有父工具调用头 | 保留它并回传父任务进度 | 丢弃全部父关联，进度回传缺失 |
| 只有空值的父任务头 | 拒绝 | 被当成缺省元数据接受 |

本次仅临时移植候选的两个关键语义：`subagent_input_id` 改为候选的 mode/thread/prompt/rich_text/text 内容摘要；`parent_headers` 改为缺一个头就丢弃整个关联。并未整体应用原 PR，也没有放宽普通主对话缺省 ID 的现有约束。实验后两个生产文件已恢复，与基线无差异。
